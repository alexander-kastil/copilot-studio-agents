# Takeaways

## Content

- An unattended run has nobody to ask: the **instructions** carry the whole job, the tools use maker credentials
- Put `reason` only on the step that has to **weigh several rules**
- Route on **descriptions** that each claim one job, and prove every route in the activity map
- Let developers own a **Foundry specialist** and connect it over the Activity Protocol
- Gate changes on a **test set** with a comparing method, one change per run

## Speaker Notes

Close the module with the habits it built, one per topic.

Unattended runs: CS-Returns Agent answered by mail only after one sentence named the mail tool, and its tool ran on maker-provided credentials because nobody was there to sign in.

Reason on one step: the ticket backlog put reason on the ranking step only, and a simple question still ran on the fast path.

Descriptions and routes: the travel planner's descriptions each claim one job and name what they exclude, and the activity map showed each question landing in exactly one specialist.

Foundry and test sets: the developer team keeps the Foundry specialist's model, tools and versions, and a test set with Meaning match caught the answer Answer quality passed. GitHub Copilot agents in module 6 run the same orchestration idea always on.
