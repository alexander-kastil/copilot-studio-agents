# A prompt agent in Microsoft Foundry
### Model, instructions and tools behind a stable endpoint
- A **Foundry project** groups agents, files and tools inside an Azure subscription
- A **prompt agent** is configuration only: a model, instructions and optional tools
- Every saved change creates an **immutable version**; you pin the one the endpoint serves
- The endpoint takes a **Microsoft Entra** sign-in; API keys aren't supported

# Voice agents
### A phone menu that answers to speech and the keypad
- **Basic** voice agents use classic orchestration; **real-time** voice agents use generative orchestration
- DTMF keys map the keypad to the menu: 1 for Account, 2 for Device, 0 for a person
- The **Speech & DTMF** chat mode tests a call in text, and `/DTMFkey 1` presses a key
- A post-call topic runs on **End of conversation** and filters on `Conversation.EndReason`

# What Answer quality misses
### A confident answer from the wrong source can pass it
- **Answer quality** judges the reply alone and never reads the expected response
- The planner answered the canteen question with a full menu from public school web pages
- Answer quality passed it; **Meaning match** scored it 0 against "has no access"
- Pair Answer quality with a **comparing method** on cases with one right answer

# Takeaways
### What to carry into the GitHub Copilot agents module
- An unattended run has nobody to ask: the **instructions** carry the whole job, the tools use maker credentials
- Put `reason` only on the step that has to **weigh several rules**
- Route on **descriptions** that each claim one job, and prove every route in the activity map
- Let developers own a **Foundry specialist** and connect it over the Activity Protocol
- Gate changes on a **test set** with a comparing method, one change per run
