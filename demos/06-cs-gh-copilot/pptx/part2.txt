# The enhanced orchestration runtime
### How one question becomes a plan across sources and tools
- **Build tab**: Instructions, Knowledge, Tools and Skills sit in one components panel
- **Always on**: every GitHub Copilot agent runs this runtime; there is no setting to pick
- **Multi-step plans**: one question can draw on several knowledge sources and tools and come back as one answer
- **Deep reasoning**: applied on its own to complex tasks, or forced with the keyword `reason` in an instruction
- **Visible plan**: the step list in Preview shows each step, and History keeps every Preview session

# Agent skills
### A SKILL.md recipe that loads when a request matches its description
- **SKILL.md**: YAML front matter with a name and a description, then Markdown instructions
- **On demand**: only names and descriptions stay in context; the full instructions load on a match
- **Description**: the runtime activates a skill from it alone, so it carries the caller's words
- **Portable**: the same open format as Claude Code and GitHub Copilot, uploaded or downloaded in the Skills panel
- **With tools**: a skill has no live connection of its own, but it can direct the agent to use a tool

# Testing a skill in Preview

name: doctor-appointment-request-drafter
description: Draft an appointment request to the company doctor
  ONLY when the employee explicitly asks to book, request, or
  schedule an appointment, a pre-travel check, or a fit-to-travel

# Connectors, MCP servers and workflows
### Which tool fits which job
- **Connector**: one action against one service, such as sending one email
- **MCP server**: one connection to a shared set of tools; its description tells the orchestrator when to call it
- **Workflow**: a repeated multi-step process, tested node by node and versioned in the new designer
- **Agent node**: a workflow step that hands a task to your agent and passes the result on

# Adding an MCP server
### One connection, every tool the server exposes
- **Add a tool**, MCP tab for a prebuilt server, or **Model Context Protocol** for your own
- Server name, **description**, URL and authentication: None, API key or OAuth 2.0
- **Edit tool** lists every tool the server exposes under **Tool permissions**
- The orchestrator calls the server on its own when a question matches the description

# Grounding with Work IQ, Foundry IQ and Fabric IQ
### The agent reads each source where it lives
- **Work IQ** reads your Microsoft 365 email, meetings, chats and files
- **Foundry IQ** answers over a knowledge base a team tunes in Microsoft Foundry
- **Fabric IQ** answers data questions from a semantic model in Microsoft Fabric
- Copilot Studio holds only the **connection**; each source stays with its owner
