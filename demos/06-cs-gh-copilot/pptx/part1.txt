# Matching the harness to the task
### Light tasks stay Standard, heavy ones earn the GitHub Copilot harness
- **Light task**: bounded data, stable actions, one main outcome, so the **Standard** harness is enough
- **Heavy task**: longer, several systems, large files, a route that changes from run to run
- On a simple task the **GitHub Copilot** harness adds reasoning, latency and **Copilot Credits**
- In a shared solution, **Standard** agents stay the responsive layer and a scheduled **GitHub Copilot** agent curates the data

# Bounding the agent's loop
### The route is planned, the limits are set
- The agent asks for missing inputs, plans, runs the steps it may run and checks its **evidence**
- A safe gap means **replanning**, which never widens permissions or works around a denial
- A denial, a failed safety rule or a reached **limit** stops the run as partial or blocked
- The loop ends in a **draft with evidence**; a person or workflow takes the consequential step

# What the harness leaves to you
### Read-only tools, approval and credentials are design decisions
- Give the agent **read-only tools** and keep write access behind a **workflow**
- With **maker credentials** every user acts with the maker's permissions
- A failing **hook** lets the agent continue; **Request for information** is Outlook only and first response wins
- Everything the agent reads is **data**; files last **28 days**, memory is private
