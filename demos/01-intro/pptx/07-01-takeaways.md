# Takeaways

## Content

- Every agent is a copilot with a **narrower job and more autonomy**
- An agent works toward a **goal** in a loop, and a person approves consequential actions
- Fix a weak agent by naming its thin part: **instructions, knowledge or tools**
- Choose the **harness** before you create the agent: it fixes behavior, features and billing
- Take the **lowest-effort path** that meets the need, and set **Copilot Credit** limits before the first bill

## Speaker Notes

Close the module with the habits it built, each one a decision you make before you start building.

Narrower job, more autonomy: a copilot answers turn by turn, while an agent takes a specific job with its own knowledge, instructions and tools.

Goal and approval: an agent plans, acts, observes and adjusts until the outcome is reached, and a person approves before an action such as sending an email runs.

Name the thin part: confident but wrong answers, off-topic replies and no access to current data each point to one of instructions, knowledge or tools.

Harness first: the standard, GitHub Copilot, Copilot chat and Customer Conversation harnesses run the same agent design differently, and an agent can't move from one to another, so the harness is decided before the build starts.

Lowest-effort path and limits: start with Agent Builder, a SharePoint agent or a Cowork skill, and move to Copilot Studio when a tool call, a channel or a multi-step process requires it. Agents bill in Copilot Credits, so set monthly and per-user limits at activation; the Cowork module builds on this next.
