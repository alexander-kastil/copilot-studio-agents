# What you design in every agent
### Instructions, knowledge and tools in a Copilot Studio agent
- **Instructions** set the role, tone and scope, here the onboarding agent's rules and examples
- **Knowledge** grounds answers in your content through RAG, here a SharePoint site
- **Tools** act on live systems, often through an MCP server; this agent has none yet
- A weak agent is thin in one part: **name which one** to fix it

# One lifecycle on every harness
### Create, build, test, publish, monitor, then improve
- Every agent is **created, built, tested, published and monitored**, whatever harness runs it
- A test chat shows **one example**; an evaluation runs **a fixed set** you can compare
- Monitor shows **real use**, and each finding becomes one focused change
- The tab names differ by harness; **the stages don't**
