# Running and tuning a skill

## Content

- **Run it by name** in a new task, then check every claim against the source
- Ask which phrasings **miss the skill** and which instruction let weak claims through
- Cowork folds the fixes in through an **Edit file?** card at Medium risk
- The **Skill Report** scores the skill out of 100; 70 counts as ready to share
- Done when it **fires without being named** and saves Aurora Trail Capsule AW26.pptx

## Speaker Notes

This slide closes the topic with the loop the product-pitch demo follows once the skill is saved. The screenshot shows where it ends: the Aurora Trail Capsule AW26 deck, built from a prompt that never named the skill.

Run it by name: start a new task, because discovery happens at the start of a conversation, and run the skill against aw26-market-brief.docx. Then ask Cowork to quote the line in the brief behind every claim on The shift, The gap and Why Aurora.

Miss the skill: ask which pitch requests phrased the way you talk would fail to trigger it, such as a sell-in deck for your accounts. Tie each weak claim to the instruction that let it through.

Edit file?: accept Cowork's offer to apply the fixes, and it holds an Edit file? card for SKILL.md at Medium risk before it overwrites anything. A new task started a few minutes later already uses the edited skill.

Skill Report: Cowork scores every skill you create or update from 0 to 100 across trigger clarity, instruction specificity, scope boundaries and robustness, 25 points each. A low trigger clarity score usually points at the description.

Fires without being named: ask for a partner deck for the AW26 trail-running capsule in your own words, and the step log reads Reviewed custom skill Product pitch. The commercial cards stay as bracketed placeholders until you supply the input, and in the class run the title card's promise did too.
