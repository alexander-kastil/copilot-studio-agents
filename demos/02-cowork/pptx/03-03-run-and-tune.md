# Running and tuning a skill

## Content

- **Run it by name** in a new task, then check the output against the template and the source
- Ask Cowork which phrasings **miss the skill** and which instruction let weak output through
- The **Skill Report** scores trigger clarity, instruction specificity, scope boundaries and robustness, 25 points each
- Bands: **Excellent** 85+, Good 70-84, Needs work 50-69, Poor below 50
- A skill is done when it **fires without being named**

## Speaker Notes

This slide closes the topic with the loop both demos follow once the skill is saved. The diagram cycles through five steps until the skill triggers on natural phrasing.

Run it by name: start a new task, because discovery happens at the start of a conversation, and run the skill against a real source. In the product-pitch demo every claim on The shift, The gap and Why Aurora must quote a line in the brief.

Miss the skill: ask which requests phrased the way you talk would fail to trigger it, and which instruction let the weak claims through. Fold both fixes into the SKILL.md by widening the description and sharpening the weak instruction.

Skill Report: Cowork scores every skill you create or update from 0 to 100 across four dimensions worth 25 points each. Start with the lowest-scoring dimension; a low Trigger clarity usually points at the description.

Bands: the score falls into Excellent, Good, Needs work or Poor. The report also flags a description over the character limit, missing trigger phrases, a skill that is too broad, and two skills competing for the same requests.

Fires without being named: save the edit, start a new task and ask in your own words, for example "Prep me for my next Fjallbryggan call". Both demos end on this check.
