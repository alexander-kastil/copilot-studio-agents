# Identity, tools and preview limits

## Content

- The **email address** uses your alias as a fixed prefix and cannot change after publish
- **Agent account** becomes the default authentication for every tool that supports it
- **End-user authentication** still needs each person's consent through Go to Agent Management
- **Preview limits**: no external users, no co-authoring, email replies up to 250 people
- It cannot read files labeled **Confidential** or **Internal Only**

## Speaker Notes

Some account decisions are final once you publish, and some preview limits shape the process design. Plan both before the first publish, as the two people in the photo do at the whiteboard.

Email address: your alias is a fixed prefix and the agent reports to you. Neither can change during the preview, and the address cannot change after publish.

Agent account authentication: it becomes the default for every tool that supports it. You can change it per tool, and the account does not grant every permission automatically.

End-user authentication: tools set this way still need each person's own consent through Go to Agent Management. Grant only the access the job needs.

Preview limits: the agent does not respond to anyone outside the tenant and does not edit existing documents in place. It replies only in conversations with up to 250 people (error reference MCS-4043).

Protected documents: files labeled Confidential or Internal Only are out of reach. A review agent that writes a fresh document each cycle works today; one that edits a shared tracker in place does not.
