# Overview

## Content

- **Meet Autopilot**: what makes an agent a teammate and where Autopilot sits
- **Working with Autopilot**: the brief, background work and approvals
- **Agent accounts**: a Copilot Studio agent with its own identity
- **Proactive teammates**: triggers, email and Teams mentions
- **Shared memory, licensing and governance**: what the tenant needs first

## Speaker Notes

The module follows the two ways Microsoft 365 delivers a teammate today, and the diagram places each topic on one of them. Topics 1, 3 and 5 carry the core path; topics 2 and 4 deepen it for tenants with preview access.

Meet Autopilot: we start with the four properties that make an agent a teammate. Then we place Autopilot beside Chat, Cowork, Code and Copilot Studio agents.

Working with Autopilot: how you brief it, how it keeps working in the background, and which actions still stop for your approval.

Agent accounts: the maker path. You give a Copilot Studio agent its own Entra ID, mailbox and Teams presence and publish it.

Proactive teammates: triggers make the agent act without a prompt. The Cadence example ties the schedule, the tools and the reviewers together.

Shared memory, licensing and governance: both paths end here. Shared memory, the per-agent license pool and the admin activation steps decide whether anyone can build at all.
