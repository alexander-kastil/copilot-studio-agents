# Takeaways

## Content

- Learn the **classic** model first: the New Experience reuses its concepts under one Build surface
- Use a topic for a precise flow and **knowledge** for open questions over your content
- Pick each **tool** for its job: connector, Dataverse, MCP server, REST API or computer use
- Turn on **generative orchestration** for autonomy, multi-agent handoffs and deep reasoning
- Publish to make edits live, then add the **channel** your colleagues already use

## Speaker Notes

Close with the habits the module was built around, from a first grounded agent to the New Experience.

Classic first: the classic surface is what most tenants open and where production agents and ALM pipelines live. The New Experience reuses the same concepts under a consolidated Build surface, so it reads as a rearrangement.

Topics and knowledge: a precise, repeatable flow belongs in a topic, and open-ended questions belong to knowledge and generative answers. Good names and descriptions let the orchestrator choose.

Tools: each tool type has a job it does best, and choosing the right one is the maker skill. A connector does one action in a known service, an MCP server shares a versioned toolset, and computer use drives an app with no API.

Orchestration: autonomous behavior, multi-agent handoffs and deep reasoning all depend on generative orchestration being turned on. Agent flows keep the fixed steps deterministic.

Publish and channel: publish is what makes edits go live, and a channel such as Teams brings the agent to colleagues. Module 04 picks up publishing, ALM and governance from here.
