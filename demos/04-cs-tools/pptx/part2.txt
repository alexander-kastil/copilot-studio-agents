# How the agent fills tool inputs
### Dynamically fill with AI or a custom value, per input
- **Dynamically fill with AI** (the default) takes the value from the conversation or asks for it
- A **custom value** is fixed: a value, a variable or a formula such as `System.User.Email`
- The Teams tool keeps Post as, Post in and Post message request on dynamic filling
- The orchestrator chooses the tool by its **name and description**, so rename it after Add and configure

# Whose credentials a tool uses
### End user credentials ask each person to connect once
- **End user credentials** (the default): each person connects on first use and acts with their own access
- **Maker-provided credentials** run every call with the author's access
- Maker-provided credentials need an **authenticated channel**, and admins can turn them off
- The Publish dialog then warns: "Your agent runs tools that use the author's credentials."

# A reviewer before the Teams post
### The agent gets its answer first, the post waits for a person
- **Respond to the agent** sits right below the trigger, so the chat gets its answer at once
- **Request for information** emails the reviewer a Posting Control request through Outlook
- The flow posts to the Teams channel only after the reviewer selects **Submit**
- An agent waits at most 100 seconds for a flow; the review step runs on after the response

# Tool descriptions the orchestrator routes on
### A description can also set the call order
- Each description names the **job**, the data and when to use the tool
- "Look the dish up with CS-Gets all food first" sets the **call order**
- Without that line the agent guessed an id and got **Not Found**
- The wizard asks for a description of **every input and output** before Next turns on
