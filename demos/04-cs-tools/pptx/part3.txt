# Tool discovery with MCP
### A connector is fixed at import, an MCP server lists its tools at runtime
- A **custom connector** keeps the operations of the OpenAPI file you imported
- An **MCP server** answers `tools/list` at runtime with its current tools
- Tool descriptions come from the server's `[Description]` attributes, so a vague one is fixed there
- **Adding a tool** means adding a method and restarting the server
- MCP needs **generative orchestration**, and topics cannot call a server directly

# Takeaways
### Pick the tool by the job
- A **prompt** for the canteen order, an **agent flow** for fixed steps, a connector or REST API for one service
- **MCP** for a toolset many agents share, **computer use** only where no API exists
- The orchestrator chooses by **name and description**, so write them in your users' words
- Rows, posts, shifts and mails go out **after a confirmation**, with credentials you chose on purpose
- The **activity map** shows which tool ran and what it was given
