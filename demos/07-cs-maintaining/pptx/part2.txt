# What a solution carries
### And what you set up after deployment
- A **custom solution** carries the agent and the objects it needs
- **Environment variables** and **connection references** hold the settings that change per environment
- **Deployment pipelines** promote in one click inside Copilot Studio; Azure DevOps or GitHub run pro-dev CI/CD
- **Native Git integration** keeps a source of truth outside Dataverse
- Deployed channels, authentication settings, sharing and Application Insights need **post-deployment steps**

# Web channel security and Direct Line
### The secret stays on the server, the client gets a token
- **Require secured access** makes every client present a secret or a token
- The **secret** lives only in server code; browsers and apps get a **token**
- Two secrets work at once, so you **rotate without downtime**
- The app starts a conversation, posts messages and reads replies over **Direct Line**

# Building and migrating from the terminal
### The Grey Logistics IT Help Desk, cloned, extended, published and migrated
- **Clone first**: the plugin works only on an agent that already exists in an environment
- The **Advisor** ranks findings High, Medium and Low; the **Author** writes a validated VPN topic
- **Pull before you push**: the push lands as a draft for the Test pane
- **Publish**, then point test with "My VPN won't connect on my laptop"
- **/mcs-assistant:migrate** builds GH-Grey Logistics IT Help Desk; the original stays unchanged

# Takeaways
### From a personal sandbox to production
- Build in a **custom solution**, set as preferred, from the first component
- **Publish** once to every channel and choose the **authentication model** with care
- Promote with **pipelines and Git**, then finish the **post-deployment steps**
- Let a **coding agent** author, validate and push the agent as files
