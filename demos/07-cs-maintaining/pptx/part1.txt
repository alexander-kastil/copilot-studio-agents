# Overview
### Five topics along the lifecycle of an agent
- **Environments and solutions**: development, test and production, with Dataverse holding the solution
- **Microsoft channels**: one publish reaches Teams, Microsoft 365 Copilot and SharePoint
- **ALM and source control**: deployment pipelines and Git move the solution forward
- **Advanced channels** (optional): websites, Direct Line and WhatsApp
- **Agentic building**: a coding agent clones and pushes the agent as files

# Publishing and channels
### One publish updates every connected channel
- **Publishing** creates the live version; nobody can use the agent before you publish
- One publish updates **every connected channel** at once
- **Microsoft channels**: Teams and Microsoft 365 Copilot, and SharePoint
- The **authentication model** is chosen at publish time: Entra ID by default, manual or none

# Authentication and channel choice
### The Channels page of a published agent
- **Published agent status** shows who published and when
- With **Microsoft authentication**, only Teams and Microsoft 365 and SharePoint are available
- Other channels need **manual** or **No authentication**
- No authentication lets anyone with the link chat and blocks tools that rely on **user credentials**

# Republishing a change
### One publish, then a new session in Teams
- Every change reaches users only through **Publish**
- A running conversation keeps the old version until a **new session** starts
- **start over** forces the new session in Teams
- The last answer ends with the **new sentence** from the republished topic

# ALM for Copilot Studio agents
### Development, test and production, always in solutions
- **Three environments**: development, test and production
- Customize **only in development**
- Always work **in the context of solutions**
- Decide **managed or unmanaged** when you import
- Pipelines and source control make each release **automated and auditable**
